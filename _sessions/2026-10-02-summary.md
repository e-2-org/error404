# error404 redevelopment: session summary

2, 3 and 8 October 2026, working with Claude Code on the `develop` branch, and 12 October on the `plain-css` branch. The full conversations are in [2026-10-02-transcript.md](2026-10-02-transcript.md).

## Where things stood

The 2023 start converted about 20 of the original piece's roughly 145 popup windows into hand-written CSS animations, covering the first 70 seconds of a 20-minute piece. Doing this by hand was slow because each popup's timing in the original is relative to the popup that opened it, so every open time had to be traced back up the chain of windows.

## What was built (2 October)

**Timeline extractor** (`_scripts/extract-timeline.js`, `npm run timeline`). Rather than converting the original scripts by hand, this runs them. Each popup's script from `_old/` is executed in a sandbox against a virtual clock and a virtual screen. The extractor records every window that opens, moves, scrolls, comes to the front or closes, and writes `_data/timeline.json`. That file covers 169 windows over 1212.5 seconds.

- It emulates Netscape 4, which kept windows on screen. One window, `03text05`, was opened below the bottom of the screen and is clamped to the bottom edge.
- Window positions allow for the window frame and title bar (6px wide, 26px high), as the original's `winx()`/`winy()` did.
- The original pages are Windows-1252 encoded and are decoded as such, so curly quotes come through correctly.
- The typing text comes from the tinyType applet's parameters: 8,805 characters at 137.7ms each, spread over the typing window's lifetime.

**Player** (`_includes/javascript/`). A single clock (`clock.js`) drives everything, so the windows (`windows.js`) and typing (`typing.js`) stay in step.

- `?t=<seconds>` starts part way through, and `?debug` shows the time.
- Space pauses; the arrow keys skip 10 seconds, or 60 with shift.
- The desktop is always 1024x768, scaled to fit the browser window like a monitor.

**Desktop themes.** These are chosen from the viewer's platform by a script in the `<head>` (`theme.js`), as the original chose between `e2.css` and `e2_mac.css`. They can be overridden with `?os=mac` or `?os=win`, or from the start dialog.

- **Windows 98** (`_sass/themes/win98.scss`): teal desktop, taskbar and inactive title bars.
- **Mac OS 8 Platinum** (`_sass/themes/platinum.scss`): striped title bars, the ChicagoFLF font (public domain), a menu bar and a desktop pattern.
- No real Apple or Windows logos are used.

### Other changes

- Removed `_data/windows.yml`, `_data/typing.yml`, `_sass/xp.scss` and `styles.js`; they're still in git history.
- Fixed `_scripts/minify.js`, which was writing to a path the page didn't load.
- The footer script tag now uses `relative_url`.
- Added a start dialog and a "Play again" dialog at the end.

## What was added (3 October)

**Video capture** (`_scripts/capture.js`, `npm run capture`). Renders the piece to video at 1024x768, 30fps, one video per desktop theme: `output/error404-win.mp4` and `output/error404-mac.mp4`.

- The player has a `?capture` mode: it doesn't play, and `window.renderAt(ms)` draws any moment of the piece.
- The typing cursor blinks in time with the piece instead of with a CSS animation, so renders are identical every time.
- The desktop clock starts at `--clock` (default 12:00; `--clock now` uses the time the render starts) and runs with the piece. In the browser the clock shows the viewer's own time.
- None of the GIFs the piece uses are animated, so every frame can be rendered exactly.
- The piece is split into chunks rendered in parallel (each in its own browser, so none is a throttled background tab), then joined without re-encoding. Each theme takes about 8½ minutes with 6 jobs.
- `output/` is in `.gitignore` and Jekyll's `exclude`.

**Screenshot button** (`_includes/javascript/screenshot.js`). A camera button under the fullscreen button. It plays a shutter sound (synthesised with Web Audio), flashes the screen white and saves a 1024x768 PNG named after the theme and the moment in the piece, e.g. `error404-mac-04m12s.png`.

- This replaced an earlier idea of using the Print Screen key, which browsers can't reliably see (macOS keeps its screenshot shortcuts to itself).
- The image is made by html-to-image, loaded from jsDelivr the first time it's used. Only open windows are included.
- The copied styles include logical properties (`inset-inline`, `inset-block`), which have to be reset as well as `left`/`top` to stop the screenshot being offset.

**Taskbar and menu bar dead zones.** Windows no longer go behind the Windows taskbar or the Mac menu bar. The extractor now emulates a 1024x740 screen (768px less the 28px taskbar; the Mac menu bar is 20px, so the Mac desktop has an 8px spare strip at the bottom). The original scripts then place windows above the taskbar themselves. Three windows taller than the desktop (`text07`, `text19`, `text60`) are shrunk to fit.

**Taskbar.** Only the main "404 NOT FOUND…" window has a taskbar button.

### Closer to Mac OS 8

- Only the frontmost window shows the close box, the zoom and collapse boxes and the striped title bar; other windows have a plain grey title bar with a grey title, as in Mac OS 8.
- The close box had never shown on any window, because of a wrongly nested SCSS selector. Fixed.
- Titles are centred across the whole title bar. They had been pushed right by a spacer placed in the wrong order.
- A darker drop shadow down the right and bottom edges, and a content area set into the frame.
- All drawn with CSS, with no Apple artwork.

**Title bar shimmer fix.** The Mac title bar stripes shimmered as windows moved, because the desktop is scaled to fit the browser by an uneven factor and the 1px stripes landed on screen pixels differently each frame. The desktop and every window are now positioned on whole screen pixels (`Desktop.fit()` and `Windows.render()`, allowing for zoom and high-DPI screens). A test of a moving Mac window at a scale of 1.04 went from 2 alternating stripe patterns to 1.

### Fixes along the way

- `.gitignore`: appending `output` merged it into the last line as `Gemfile*output`, because the file had no final newline. Fixed.

## What was looked at (8 October)

**The missing postcard at about 322 seconds.** The typed line "...for example a postcard read...." finishes at about 327s, but nothing opens between `text11` closing (315.7s) and the dodecahedron (334.7s). This is how the original was scripted, not an extraction fault:

- In the original `index.html`, `Focus5` opens the postcard title at 286s and the next cue, `dodectimer`, opens the dodecahedron at 334.5s. The postcard title's own chain (ruin, tower, pyramid, `text11`) is finished by 319.7s.
- Every page in `_old/error404` is in the timeline, apart from `acab.html` (the end page).
- Four other copies were compared with `_old`: the CD image (`_old/CD/Image.nrg`) and the backups in `/mnt/data/archive/wf` for e-2.org, annabest.info and c-ship.org. All have the same acts 5 and 6. The CD's `06TEXT12.HTM` is just the shortened CD name for `06text15a.html`, and the older c-ship.org copy differs only in its ending. The FTP upload log lists no files that are missing locally.
- No file named `text12` or `text13` exists anywhere in `/mnt/data/archive`.
- The text windows jump from `text11` to `text14`, so two postcard texts were probably planned and never made.

**The origami list window (`text15a`) never showed.** `06beardteacher.html` opened it full screen, and its `MoveDown` script (1px down every 100ms until it reaches the bottom of the screen, then close) closed it straight away. It now works as intended, through a new `ADJUSTMENTS` table in `extract-timeline.js` for windows that didn't work as intended in the original:

- It opens 240px short of the desktop height (474px content area), so it moves down for 24 seconds as scripted: from 349.95s to 373.75s, before act 7 at 375.7s. (A first try at half the screen height took 37 seconds and ran into act 7.)
- Its content scrolls as it moves, ending with the last line of text ("...to Doug.") at the bottom of the window, so the empty lines at the end of the page stay out of view. The scroll target is 943px: the last line ends 1409px down in both themes, plus the 8px margin, less the window height. These were measured in headless Chrome and are hard-coded, so they need re-measuring if the window's fonts or margins change.

## What was changed (12 October)

On a new `plain-css` branch.

**Plain CSS.** The Sass is replaced by plain CSS using nesting and custom properties. `assets/css/style.css` imports the layout both themes share (`assets/css/partials/`) and both themes (`assets/css/themes/win98.css`, `assets/css/themes/platinum.css`). Every theme rule is nested under the theme's class, `.os-win` or `.os-mac`, with the theme's colours, font and bevelled borders as custom properties on that class. Font paths gained a level (`../../fonts/`), and the theme rules are now one class more specific, which changes nothing as they were already meant to win over the shared layout.

**Both themes loaded, chosen by a class on the body.** The `<body>` starts as `os-win`, which is also the theme without JavaScript. `theme.js` now runs as an inline script at the start of the body, before anything is drawn, and switches it to `os-mac` where needed (from `?os=`, the choice remembered from the start dialog, or the platform). The start dialog (`desktop.js`) and the screenshot file name (`screenshot.js`) use the body's class; there is no stylesheet link to swap any more, and the `<noscript>` stylesheet in the head is gone.

**ES modules.** The JavaScript moved from `_includes/javascript/` to `assets/js/` as ES modules, each exporting its object (`Clock`, `Desktop`, `Windows`, `Typing`, `Screenshot`, `initFullscreen`) and importing what it uses. `main.js` (the old `playlist.js`) is the entry point, loaded with `<script type="module">` in `_includes/foot.html`, and starts everything straight away, as modules run once the page has been read. `desktop.js` and `windows.js` import each other, which is fine because each only uses the other when it runs. Only `theme.js` stays in `_includes/javascript/`, as an inline script. Removed: uglify (`npm uninstall`), `_scripts/minify.js`, `assets/js/bundle.js` and `bundle.min.js`, and `utilities.js` (`waitForMs`, which nothing used). `npm run build` now just regenerates the timeline.

**Close boxes.** Clicking the close box on the typing window (`scroller`) or Mrs L (`carla`) no longer closes them: the click listener in `windows.js` skips the windows listed in `Windows.permanent`.

**Checks.** The new build was compared with `develop` pixel by pixel in capture mode: both themes at 5s, 80s, 225s, 350s, 760s and 1205s, and the start dialog, with the CSS and JavaScript changes together. All 14 screenshots are identical. In headless Chrome: switching to Mac from the start dialog changes the body's class and is remembered on reload; starting, pausing and `?t=` work; the fullscreen and screenshot buttons show; and in both themes the typing window and Mrs L stay open when their close boxes are clicked, while an ordinary window closes. The README is updated.

## Findings

- The piece was composed for a 1024x768 screen: the original launcher warned users with smaller screens.
- Mrs L's lap of the screen takes about 314 seconds (1px every 100ms), not the 120 seconds in the 2023 CSS.
- At 73 seconds the original reopens the "Planets List" window, snapping it back to its start position. This is kept.
- The original has no window between 320s and 334s, although the typed text announces a postcard there.
- The only postcard text window, `text10` ("I Am Forever In Debt To Your Priceless Advice / this reply was on a postcard."), opens at 251.7s, before the postcards section of the typed text starts at about 258s. This is as the original was scripted.
- `04text10.html` and some other original pages are not UTF-8, so a plain `grep` can treat them as binary and miss them.
